# Panda 逆动力学与关节阻抗保持 Demo 详解

本文详细讲解 [`demos/panda_dynamics_hold.py`](../demos/panda_dynamics_hold.py)。

如果只用一句通俗的话概括这个 Demo：

> 先让控制器记住机械臂启动时的姿势，再把每个关节想象成装了一根弹簧和一个减震器；当外力把机械臂推离原位时，控制器会抵消重力，并把机械臂平稳地拉回启动姿势。

它演示的不是轨迹规划，也不是直接指定末端执行器的三维坐标，而是一个典型的**关节空间阻抗保持控制器**。

---

## 1. 这个 Demo 最终想实现什么

程序启动后会完成以下事情：

1. 从 MuJoCo 的 `home` keyframe 读取 Panda 的初始姿态。
2. 把前 7 个机械臂关节的初始角度保存为目标角度。
3. 使用 Pinocchio 计算机械臂当前姿态下的动力学补偿力矩。
4. 根据“目标角度与当前角度的差”计算弹簧力矩。
5. 根据关节速度计算阻尼力矩。
6. 将三部分力矩相加，并限制在执行器允许的范围内。
7. 把最终的 7 维力矩发送给 MuJoCo 的 7 个机械臂执行器。
8. 当机械臂被鼠标拖开后，使它逐渐回到启动姿态。
9. 关闭 viewer 后，绘制力矩和关节误差曲线。

正常运行时可以观察到：

- 不施加外力时，机械臂基本维持在初始姿态；
- 拖动机械臂时，会感到一种“越拉越想回去”的弹簧感；
- 松手后，机械臂不会停在新位置，而会回到原来的目标姿态；
- 阻尼会消耗运动能量，避免机械臂在目标附近长时间来回振荡；
- 当请求力矩超过模型限制时，程序会限幅并打印 `[SATURATED]`。

## 3. 先理解“保持”的含义

这里的“保持”指的是：

```text
让 7 个关节角尽量保持在程序启动时记录的目标角度
```

目标关节角记作：

\[
q_d =
\begin{bmatrix}
q_{d,1} & q_{d,2} & \cdots & q_{d,7}
\end{bmatrix}^{T}
\]

当前关节角记作：

\[
q =
\begin{bmatrix}
q_1 & q_2 & \cdots & q_7
\end{bmatrix}^{T}
\]

代码在初始化时执行：

```python
self.target_arm_q_rad = self.data.qpos[:ARM_DOF].copy()
```

这里一定要使用 `.copy()`。如果只保存一个指向 `data.qpos` 的视图，那么 MuJoCo 更新状态时，所谓“目标角度”也可能跟着改变，控制器就失去了固定目标。

### 它是不是在保持末端静止

可以说“间接保持”，但不能说它直接控制末端。

| 问题 | 本 Demo 的答案 |
|:---:|:---:|
| 直接控制的量 | 7 个关节角 |
| 目标量 | 启动时的 7 维关节姿态 |
| 是否显式计算末端位置误差 | 否 |
| 末端为什么也会回去 | 同一组关节角通常对应同一个末端位姿 |
| 是否属于笛卡尔空间阻抗 | 否 |

如果目标是“末端位置必须保持在空间中的某一点，而机械臂其他关节可以自由调整”，就需要使用雅可比矩阵和笛卡尔空间阻抗控制，而不是当前的关节空间保持控制。

## 4. 核心控制公式

本 Demo 每个仿真步计算：

\[
\tau_{cmd}
=
\tau_{dyn}
+
\tau_{spring}
+
\tau_{damping}
\]

展开后是：

\[
\boxed{
\tau_{cmd}
=
h(q,\dot q)
+
K_p(q_d-q)
-
K_d\dot q
}
\]

各部分含义如下：

| 数学符号 | 代码变量 | 含义 | 单位 |
|:---:|:---:|:---:|:---:|
| \(q_d\) | `target_arm_q_rad` | 目标关节角 | rad |
| \(q\) | `arm_q_rad` | 当前关节角 | rad |
| \(\dot q\) | `arm_qvel_rad_s` | 当前关节角速度 | rad/s |
| \(K_p\) | `stiffness_nm_rad` | 关节刚度 | N·m/rad |
| \(K_d\) | `damping_nm_s_rad` | 关节阻尼 | N·m·s/rad |
| \(h(q,\dot q)\) | `dynamics_tau_nm` | 动力学补偿 | N·m |
| \(\tau_{spring}\) | `spring_tau_nm` | 拉回目标的弹簧力矩 | N·m |
| \(\tau_{damping}\) | `damping_tau_nm` | 抑制运动的阻尼力矩 | N·m |
| \(\tau_{cmd}\) | `requested_tau_nm` | 限幅前的请求力矩 | N·m |
| \(\tau_{applied}\) | `applied_tau_nm` | 实际写入执行器的力矩 | N·m |

下面分别解释三部分。

---

## 5. 动力学补偿：先帮机械臂“托住自己”

机械臂不是没有重量的数学线段。每根连杆都有质量、质心和转动惯量，因此即使关节目标完全不变，关节也需要输出力矩来抵抗重力。

常见机器人动力学方程是：

\[
M(q)\ddot q+C(q,\dot q)\dot q+g(q)=\tau
\]

还可以把速度相关项与重力项合并记成：

\[
h(q,\dot q)=C(q,\dot q)\dot q+g(q)
\]

代码调用：

```python
dynamics_tau_nm = np.asarray(
    pin.rnea(self.pin_model, self.pin_data, q, qvel, self.zero_qacc)
).reshape(-1)
```

因为传给 RNEA 的期望加速度是零：

\[
\ddot q=0
\]

所以 Pinocchio 返回的主要是：

\[
\tau_{dyn}=h(q,\dot q)
\]

也就是当前姿态和当前速度下，用来补偿重力、科氏力和离心力等模型项的力矩。

### 为什么不用速度差分计算实际加速度

旧代码使用：

```python
a = (v - last_v) / timestep
```

然后把这个估计加速度直接交给 RNEA。这个做法存在两个问题：

1. 仿真时间步很小，速度里的微小变化除以很小的时间会被明显放大；
2. 计算出的惯性力矩又立刻作用回同一个系统，容易形成噪声反馈。

本 Demo 的目标是姿态保持，不需要复现“系统刚才实际产生了多少惯性力矩”，所以使用零期望加速度更简单、更稳健。

### Pinocchio 的补偿为什么可能不是百分之百准确

MuJoCo 和 Pinocchio 分别建立并计算各自的动力学模型。即使它们读取的是同一个 MJCF，以下细节仍可能有差异：

- 关节被动阻尼
- 执行器模型
- 接触与约束
- 数值积分器
- 摩擦模型
- 夹爪联动约束
- 浮点计算误差

因此只使用模型补偿时，机械臂仍可能缓慢漂移。位置反馈项会自动纠正这种小误差，这正是闭环控制比纯模型补偿更可靠的原因。

## 6. 弹簧力矩：负责“拉回去”

位置误差定义为：

\[
e_q=q_d-q
\]

代码对应：

```python
position_error_rad = self.target_arm_q_rad - arm_q_rad
```

弹簧力矩为：

\[
\tau_{spring}=K_p e_q
\]

代码对应：

```python
spring_tau_nm = self.stiffness_nm_rad * position_error_rad
```

假设某个关节的目标角是 `0 rad`，当前被拖到 `0.1 rad`，刚度为 `50 N·m/rad`：

\[
e=0-0.1=-0.1\ \text{rad}
\]

\[
\tau_{spring}=50\times(-0.1)=-5\ \text{N·m}
\]

负号意味着控制器会向减小角度的方向施力，把关节拉回目标。

### 刚度越大意味着什么

| 刚度设置 | 拖动手感 | 回位表现 | 潜在问题 |
|:---:|:---:|:---:|:---:|
| 较小 | 软，容易拖开 | 回位较慢，静态误差较大 | 抗扰动能力弱 |
| 适中 | 有明显弹簧感 | 能平稳回位 | 通常最适合演示 |
| 较大 | 很硬，不容易拖动 | 回位很快 | 容易振荡或触发力矩饱和 |

默认值为：

```python
DEFAULT_STIFFNESS_NM_RAD = 100.0
```

表示 7 个关节默认都使用 `100 N·m/rad`。构造函数也支持传入 7 个不同的值，以便逐关节调参。

---

## 7. 阻尼力矩：负责“刹车”

只有弹簧时，机械臂可能冲过目标，再被反方向拉回来，形成持续振荡。阻尼项与运动方向相反：

\[
\tau_{damping}=-K_d\dot q
\]

代码对应：

```python
damping_tau_nm = -self.damping_nm_s_rad * arm_qvel_rad_s
```

如果某个关节以正方向转动：

\[
\dot q>0
\]

那么阻尼力矩为负：

\[
\tau_{damping}<0
\]

它会阻碍当前运动。反方向运动时同理，所以阻尼始终倾向于降低速度，而不会主动把关节拉向某个位置。

默认阻尼为：

```python
DEFAULT_DAMPING_NM_S_RAD = 20.0
```

| 阻尼设置 | 典型现象 |
|:---:|:---:|
| 太小 | 回位快，但容易越过目标并振荡 |
| 合适 | 回位平稳，振荡很快消失 |
| 太大 | 运动显得迟钝，拖动困难，阻尼力矩可能饱和 |

旧代码使用 `100 N·m·s/rad`，很小的速度就可能产生很大的阻尼力矩。优化后的默认值为 `20 N·m·s/rad`，在当前模型的短时扰动测试中能平稳收敛，同时保留可交互性。

---

## 8. 为什么弹簧和阻尼要同时存在

两者职责不同：

| 控制项 | 是否关心位置 | 是否关心速度 | 主要作用 |
|:---:|:---:|:---:|:---:|
| 弹簧项 \(K_p(q_d-q)\) | 是 | 否 | 把关节拉向目标 |
| 阻尼项 \(-K_d\dot q\) | 否 | 是 | 抑制运动和振荡 |
| 动力学补偿 \(h(q,\dot q)\) | 间接相关 | 间接相关 | 抵消机器人自身动力学负担 |

可以用汽车悬架来类比：

- 弹簧负责把车身支撑回正常高度；
- 减震器负责让车身不要上下弹个不停；
- 动力学补偿相当于提前承担机械臂自身重量，让弹簧不必主要用于抵抗重力。

## 9. MuJoCo 与 Pinocchio 的分工

| 组件 | 本 Demo 中的职责 |
|:---:|:---:|
| MuJoCo | 仿真刚体运动、接触、鼠标外力、执行器、积分和可视化 |
| Pinocchio | 根据当前 \(q\)、\(\dot q\) 计算逆动力学补偿力矩 |
| 控制器代码 | 计算误差、弹簧阻尼力矩、限幅并写入 `data.ctrl` |

数据流可以理解为：

```text
MuJoCo 当前状态 q、qvel
          │
          ├──> Pinocchio RNEA ──> 动力学补偿力矩
          │
          └──> 目标误差和速度 ──> 弹簧 + 阻尼力矩
                                      │
两部分相加 ──> 安全限幅 ──> data.ctrl[:7] ──> MuJoCo 下一步
```

这构成了一个闭环：MuJoCo 状态变化后，下一步控制器会看到新状态并重新计算力矩。

## 10. 为什么状态是 9 维，而控制机械臂只取前 7 维

这个 Panda 模型包含：

| 状态索引 | 关节 | 类型 | 本控制器是否主动保持 |
|:---:|:---:|:---:|:---:|
| 0～6 | `joint1`～`joint7` | 旋转关节 | 是 |
| 7 | `finger_joint1` | 夹爪滑动关节 | 否 |
| 8 | `finger_joint2` | 夹爪滑动关节 | 否 |

Pinocchio 的模型维度是完整的 9 维，所以调用 RNEA 时传入完整的：

```python
q = self.data.qpos.copy()
qvel = self.data.qvel.copy()
```

但本 Demo 只向前 7 个机械臂力矩执行器写值：

```python
self.data.ctrl[:ARM_DOF] = applied_tau_nm
```

夹爪控制值从 `home` keyframe 中初始化，并由模型自己的夹爪执行器处理。

## 11. 每个控制周期具体发生什么

`CustomViewer.run_loop()` 的主要顺序是：

```text
mj_forward
   ↓
runFunc：读取状态并计算控制力矩
   ↓
mj_step：推进一个仿真时间步
   ↓
viewer.sync：刷新画面和鼠标扰动
```

`runFunc()` 内部进一步分为：

1. 复制完整的 `q` 和 `qvel`；
2. 取出前 7 个机械臂关节状态；
3. 调用 RNEA 得到动力学补偿力矩；
4. 计算目标关节角误差；
5. 计算弹簧力矩；
6. 计算阻尼力矩；
7. 合成请求力矩；
8. 检查是否出现 `NaN` 或无穷大；
9. 按 MJCF 的 `ctrlrange` 限制力矩；
10. 写入 `data.ctrl[:7]`；
11. 记录曲线数据并按固定间隔打印日志。

## 12. 力矩限幅为什么重要

模型中前 7 个力矩执行器的 `ctrlrange` 是 `[-100, 100]`。控制器不能假设任何计算结果都天然安全。

程序读取模型中的真实限制：

```python
self.arm_ctrl_range_nm = self.model.actuator_ctrlrange[:ARM_DOF].copy()
```

然后执行：

```python
applied_tau_nm = np.clip(requested_tau_nm, lower_nm, upper_nm)
```

因此：

\[
\tau_{applied,i}
=
\operatorname{clip}(\tau_{cmd,i},\tau_{min,i},\tau_{max,i})
\]

如果日志出现：

```text
[SATURATED]
```

说明至少一个关节的请求力矩超过了执行器范围。常见原因包括：

- 拖动距离过大；
- 刚度过高；
- 阻尼过高且拖动速度很快；
- 模型状态异常；
- 机器人发生剧烈碰撞。

限幅不会让所有极端情况都变得稳定，但可以避免把无限制的大力矩直接写入仿真执行器。

## 13. 如何在 MuJoCo 中测试保持效果

启动程序后，可以使用 MuJoCo viewer 的扰动交互：

1. 双击选择机械臂上的某个刚体；
2. 按住 `Ctrl` 并使用鼠标右键拖动，在竖直平面内施加扰动；
3. 按住 `Ctrl + Shift` 并使用鼠标右键拖动，在水平平面内施加扰动；
4. 按住 `Ctrl` 并使用鼠标左键拖动，可以施加旋转扰动；
5. 松开鼠标后观察机械臂是否回到启动姿态。

这里的拖动是通过 viewer 向刚体施加外力或外力矩，不是直接修改关节角。因此它适合用来观察控制器如何抵抗真实的物理扰动。

如果拖不动，通常不是鼠标坏了，而是刚度或阻尼使机械臂表现得很硬。可以先降低：

```python
stiffness_nm_rad=25.0,
damping_nm_s_rad=10.0,
```

## 14. 日志应该怎么看

日志示例：

```text
t=  1.200 s | max |q error|=  3.42 deg | applied τ=[ ... ] N·m
```

| 字段 | 含义 |
|:---:|:---:|
| `t` | MuJoCo 仿真时间，单位秒 |
| `max \|q error\|` | 7 个关节中最大的绝对位置误差，单位度 |
| `applied τ` | 实际写入 7 个执行器的力矩，单位 N·m |
| `[SATURATED]` | 至少一个关节力矩被执行器上下限截断 |

请注意，`applied τ` 不是“只用于保持末端静止”的力矩。它是以下内容的总和并经过限幅：

```text
动力学补偿 + 位置弹簧力矩 + 速度阻尼力矩
```

在机械臂完全静止且误差很小时，弹簧和阻尼项接近零，此时看到的力矩主要用于抵消重力。

## 15. 关闭 viewer 后的曲线

程序不会在运行到某个固定步数时强行绘图。关闭 viewer 后才调用：

```python
demo.plot_results()
```

这样不会在控制循环中反复阻塞仿真。

第一张图包含每个关节的三条力矩曲线：

| 曲线 | 含义 |
|:---:|:---:|
| `dynamics compensation` | Pinocchio 计算的动力学补偿力矩 |
| `joint impedance` | 弹簧力矩与阻尼力矩之和 |
| `applied total` | 经过执行器限幅后实际施加的总力矩 |

第二张图显示：

\[
q_d-q
\]

并转换为角度。拖动时误差会增大，松手并回位后误差应逐渐接近零。

历史记录使用有限长度的 `deque`，最多保留 `100000` 个采样，避免长时间运行时列表无限增长。

## 16. 怎样调整控制参数

统一设置所有关节：

```python
demo = PandaHoldDemo(
    scene_xml="model/franka_emika_panda/scene_tau.xml",
    arm_xml="model/franka_emika_panda/panda_tau.xml",
    stiffness_nm_rad=100.0,
    damping_nm_s_rad=20.0,
)
```

也可以为每个关节单独设置：

```python
demo = PandaHoldDemo(
    scene_xml="model/franka_emika_panda/scene_tau.xml",
    arm_xml="model/franka_emika_panda/panda_tau.xml",
    stiffness_nm_rad=[60, 60, 50, 50, 30, 20, 15],
    damping_nm_s_rad=[24, 24, 20, 20, 12, 8, 6],
)
```

一般来说，靠近基座的关节承担更多连杆质量，可以使用较大的增益；靠近末端的关节惯量较小，过大的增益可能使手感过硬。

推荐调参顺序：

1. 先使用较小刚度和适中阻尼；
2. 逐渐提高刚度，直到回位能力满足要求；
3. 如果出现振荡，提高阻尼；
4. 如果回位太慢且没有振荡，可稍微降低阻尼或提高刚度；
5. 持续观察是否频繁出现 `[SATURATED]`；
6. 一次只改一类参数，方便判断变化来源。

## 17. 推荐的学习实验顺序

### 实验一：完整控制器

保持默认公式：

\[
\tau=h(q,\dot q)+K_p(q_d-q)-K_d\dot q
\]

先熟悉正常的拖动、松手和回位现象。

### 实验二：只保留动力学补偿

临时令：

```python
impedance_tau_nm = np.zeros(ARM_DOF)
```

此时没有固定目标姿态。理想情况下机械臂会变得容易移动，松手后也不会主动回到启动位置；模型不完全一致时仍可能缓慢漂移。

### 实验三：去掉动力学补偿

临时令：

```python
dynamics_tau_nm = np.zeros(self.model.nv)
```

此时弹簧不仅要纠正位置，还要长期承担重力。机械臂通常会在偏离目标的位置达到新的平衡，静态误差会更明显。

### 实验四：只保留弹簧，去掉控制器阻尼

设置：

```python
damping_nm_s_rad=0.0
```

MuJoCo 模型自身仍有少量关节被动阻尼，但回位过程通常会比默认设置更容易振荡。

### 实验五：比较不同刚度

依次尝试：

```text
Kp = 20、50、100 N·m/rad
```

观察拖动难度、回位速度、最大误差和力矩饱和次数。

### 实验六：逐关节增益

让基座附近关节使用较大增益、腕部关节使用较小增益，比较统一增益和逐关节增益的差异。

所有实验都应在仿真中进行，并保留力矩限幅与非有限值检查。

## 18. 它与 drag Demo 有什么区别

| 对比项 | `panda_dynamics_drag.py` | `panda_dynamics_hold.py` |
|:---:|:---:|:---:|
| 是否有固定目标关节角 | 默认没有 | 有，启动姿态 |
| 位置弹簧项 | 无 | 有 |
| 速度阻尼项 | 有 | 有 |
| 动力学补偿 | 有 | 有 |
| 拖开后松手 | 倾向于停在附近或缓慢运动 | 主动回到启动姿态 |
| 典型手感 | 有阻尼、可拖动 | 像被弹簧拴在原位 |
| 主要学习目标 | 动力学补偿与拖动示教 | 关节阻抗与抗扰保持 |

两者最关键的区别就是这一项：

\[
K_p(q_d-q)
\]

没有它，控制器不知道应该回到哪里；有了它，启动姿态就成为明确的平衡目标。

## 20. 常见问题

### 20.1 为什么完全不动时仍然有力矩

因为机械臂需要抵抗重力。静止只表示速度和加速度接近零，不代表所需力矩为零。

### 20.2 为什么松手后不是瞬间回到目标

真实动力系统有质量和惯性。控制器只能通过有限力矩改变运动状态，阻尼还会主动抑制过快运动，因此回位需要时间。

### 20.3 为什么最后还有一点关节误差

Pinocchio 与 MuJoCo 的动力学模型并非每个细节都完全相同。有限刚度下，少量位置误差会产生弹簧力矩，用于抵消剩余的模型偏差。提高刚度可以减小静态误差，但也会提高硬度和饱和风险。

### 20.4 为什么增大阻尼后反而回位更慢

阻尼会反对任何运动，包括“正在向目标回去”的运动。阻尼太大会让系统显得迟钝。

### 20.5 为什么拖得越远，反作用越明显

弹簧力矩与位置误差成正比：

\[
\tau_{spring}=K_p(q_d-q)
\]

误差越大，回拉力矩越大，直到受到执行器力矩上限约束。

### 20.6 能不能让松手后的当前位置成为新目标

可以，但那会变成另一种交互逻辑。需要在检测到拖动结束时更新：

```python
self.target_arm_q_rad = self.data.qpos[:ARM_DOF].copy()
```

当前 Demo 故意不这样做，因为它要展示“回到固定启动姿态”。

### 20.7 这能直接用于真实机器人吗

不能直接照搬。真实机器人还需要考虑驱动器接口、厂家力矩限制、碰撞检测、急停、通信延迟、摩擦辨识、传感器滤波、重力参数误差和操作人员安全。本示例默认只面向 MuJoCo 仿真。

## 21. 阅读代码时最值得抓住的主线

不要一开始陷入绘图和日志细节。先抓住下面五步：

```python
position_error_rad = self.target_arm_q_rad - arm_q_rad
spring_tau_nm = self.stiffness_nm_rad * position_error_rad
damping_tau_nm = -self.damping_nm_s_rad * arm_qvel_rad_s
impedance_tau_nm = spring_tau_nm + damping_tau_nm
requested_tau_nm = dynamics_tau_nm[:ARM_DOF] + impedance_tau_nm
```

它们表达的物理意义是：

```text
偏离目标 → 弹簧把它拉回来
正在运动 → 阻尼让它慢下来
机器人有重量 → 动力学补偿帮它托住自己
三者相加 → 得到关节执行器需要施加的总力矩
```

这就是整个 Demo 的核心。

## 22. 总结

`panda_dynamics_hold.py` 展示了一个清晰的关节空间阻抗保持控制器：

\[
\tau
=
h(q,\dot q)
+
K_p(q_d-q)
-
K_d\dot q
\]

- 动力学补偿负责减轻重力和速度相关动力学的影响
- 弹簧项负责把机械臂拉回目标关节姿态
- 阻尼项负责消耗运动能量并抑制振荡
- 力矩限幅负责让控制命令遵守模型执行器范围
- 关节误差反馈让系统能够纠正模型不一致和外部扰动

最重要的区别是：这个 Demo 不是让机械臂“随便拖到哪就停在哪”，而是让它“可以被拖开，但松手后会回到启动姿态”。
