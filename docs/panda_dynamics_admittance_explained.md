# Panda 末端导纳控制 Demo 详解

本文详细讲解 [`demos/panda_dynamics_admittance.py`](../demos/panda_dynamics_admittance.py)。

如果只用一句通俗的话描述这个 Demo：

> 给机械臂末端一个“虚拟的力”，导纳模型把这个力转换成一小段平滑的末端位移，然后 IK 和关节位置执行器让机械臂跟随这个新目标。

它演示的是一条完整的教学链路：

```text
外力/外力矩
    ↓
虚拟质量-阻尼-弹簧系统
    ↓
末端位姿偏移
    ↓
微分逆运动学 IK
    ↓
7 个关节位置目标
    ↓
MuJoCo 位置执行器
```

需要特别说明：默认的 `-5 N` 是代码生成的**合成输入**，不是从真实六维力传感器或 MuJoCo 接触传感器测得的力。

---

## 1. 这个 Demo 想实现什么

程序启动后：

1. 把 Panda 放到 MJCF 的 `home` 姿态；
2. 记录此时的末端位置和方向，作为零外力平衡位姿；
3. 在 `0.5 s` 后施加世界坐标系 `-Z` 方向的虚拟 `5 N` 力；
4. 使用 6 维导纳方程计算虚拟位移、速度和加速度；
5. 把虚拟位移叠加到初始末端位姿上；
6. 使用阻尼最小二乘微分 IK 计算新的关节目标；
7. 把目标写入 MuJoCo 的 7 个关节位置执行器；
8. 关闭 viewer 后绘制目标位置、实际位置、导纳位移和输入 wrench。

默认参数下，Z 方向稳态位移大约是：

\[
\Delta z_{steady}=\frac{F_z}{K_z}=\frac{-5}{50}=-0.1\ \text{m}
\]

也就是末端最终向下移动约 `100 mm`。

## 3. 什么是导纳控制

导纳控制回答的问题是：

```text
如果末端受到了一个力，它应该产生怎样的运动？
```

最常见的导纳模型是一套人为设计的质量-阻尼-弹簧系统：

\[
M_d\ddot x+B_d\dot x+K_dx=F_{ext}-F_{ref}
\]

本 Demo 中没有额外参考力，因此：

\[
F_{ref}=0
\]

控制方程变成：

\[
\boxed{M_d\ddot x+B_d\dot x+K_dx=F_{ext}}
\]

整理后可直接求虚拟加速度：

\[
\ddot x=M_d^{-1}\left(F_{ext}-B_d\dot x-K_dx\right)
\]

代码中的对应关系如下：

| 数学符号 | 代码变量 | 含义 |
|:---:|:---:|:---:|
| \(M_d\) | `virtual_inertia` | 虚拟质量或虚拟转动惯量 |
| \(B_d\) | `virtual_damping` | 虚拟阻尼 |
| \(K_d\) | `virtual_stiffness` | 虚拟刚度 |
| \(F_{ext}\) | `wrench_world` | 世界坐标系输入 wrench |
| \(x\) | `admittance_offset` | 相对平衡位姿的虚拟偏移 |
| \(\dot x\) | `admittance_velocity` | 虚拟速度 |
| \(\ddot x\) | `acceleration` | 虚拟加速度 |

这里的“虚拟”很重要：这些参数不等于 Panda 真实连杆的质量、阻尼和刚度，而是人为设定的交互动态。

---

## 4. 用最通俗的方式理解三个参数

可以想象机械臂末端连接着一个虚拟小车，小车又通过弹簧和减震器连接到初始位置。

### 虚拟质量

质量决定相同外力刚施加时，加速度有多大：

\[
\ddot x\approx\frac{F}{M_d}
\]

| 虚拟质量 | 典型感觉 |
|:---:|:---:|
| 小 | 对力反应快，容易突然运动 |
| 大 | 对力反应慢，显得沉重 |

### 虚拟阻尼

阻尼与速度方向相反：

\[
F_{damping}=-B_d\dot x
\]

| 虚拟阻尼 | 典型感觉 |
|:---:|:---:|
| 小 | 容易过冲和振荡 |
| 大 | 运动平稳，但响应迟钝 |

### 虚拟刚度

刚度产生返回平衡位置的恢复力：

\[
F_{spring}=-K_dx
\]

| 虚拟刚度 | 典型感觉 |
|:---:|:---:|
| 小 | 同样的持续力会产生更大位移 |
| 大 | 同样的持续力只产生较小位移 |

在持续恒力、速度最终降为零时：

\[
K_dx=F_{ext}
\]

所以稳态位移主要由 `外力 ÷ 刚度` 决定，虚拟质量和阻尼主要影响到达稳态的过程。

## 5. 6 维向量的顺序和单位

本 Demo 统一使用：

```text
[x, y, z, rx, ry, rz]
```

对应的 wrench 顺序是：

```text
[Fx, Fy, Fz, Tx, Ty, Tz]
```

| 索引 | 运动量 | wrench | 位移单位 | wrench 单位 |
|:---:|:---:|:---:|:---:|:---:|
| 0 | X 平移 | Fx | m | N |
| 1 | Y 平移 | Fy | m | N |
| 2 | Z 平移 | Fz | m | N |
| 3 | 绕世界 X 旋转 | Tx | rad | N·m |
| 4 | 绕世界 Y 旋转 | Ty | rad | N·m |
| 5 | 绕世界 Z 旋转 | Tz | rad | N·m |

默认外力是：

```python
DEFAULT_EXTERNAL_WRENCH_WORLD = (0.0, 0.0, -5.0, 0.0, 0.0, 0.0)
```

因此只有 `Fz=-5 N`，没有旋转力矩。

### 为什么平移和旋转参数不能简单认为单位相同

虽然程序把它们放在同一个 6 维数组中，但前三项和后三项的物理单位不同：

| 参数 | 平移部分单位 | 旋转部分单位 |
|:---:|:---:|:---:|
| `virtual_inertia` | kg | kg·m² |
| `virtual_damping` | N·s/m | N·m·s/rad |
| `virtual_stiffness` | N/m | N·m/rad |

这也是默认参数前三项和后三项使用不同数值的原因。

## 7. 平衡位姿与导纳偏移

`runBefore()` 会记录初始末端位姿：

```python
self.equilibrium_position_world_m = ee_body.xpos.copy()
self.equilibrium_rotation_world = ee_body.xmat.reshape(3, 3).copy()
```

必须使用 `.copy()`，否则保存的数组可能继续跟随 MuJoCo 状态变化，所谓“初始平衡位置”就不再固定。

导纳模型计算的是相对这个平衡位姿的偏移：

\[
p_{target}=p_0+\Delta p
\]

其中：

| 变量 | 含义 |
|:---:|:---:|
| \(p_0\) | 初始平衡位置 |
| \(\Delta p\) | 导纳模型产生的平移偏移 |
| \(p_{target}\) | IK 要跟踪的新目标位置 |

这比不断修改参考位置更可靠。原实现中 `desired_pos` 与 `start_ee_pos` 指向同一个数组，更新目标时会同时改变“起点”，造成参考漂移；优化后的代码彻底分离固定平衡位姿和动态偏移。

## 8. 为什么旋转使用旋转向量

原代码把末端姿态表示成 roll、pitch、yaw，并直接对欧拉角做差分和积分。欧拉角有两个常见问题：

- 角度跨越 `-π` 和 `π` 时会发生跳变；
- 某些姿态附近存在万向锁和轴耦合。

优化后的代码把后三维导纳偏移解释为旋转向量：

\[
\Delta\theta=\begin{bmatrix}r_x&r_y&r_z\end{bmatrix}^{T}
\]

其方向表示旋转轴，模长表示旋转角。代码通过 SciPy 转换为旋转矩阵：

```python
rotation_offset_world = Rotation.from_rotvec(
    self.admittance_offset[3:]
).as_matrix()
```

目标方向为：

\[
R_{target}=R_{offset}R_0
\]

这种方式仍然主要适合小范围柔顺运动，但比直接积分欧拉角更连续、更清楚。

## 9. 数值积分是怎样做的

每一步先计算加速度：

```python
acceleration = (
    wrench_world
    - self.virtual_damping * self.admittance_velocity
    - self.virtual_stiffness * self.admittance_offset
) / self.virtual_inertia
```

然后使用半隐式 Euler：

\[
\dot x_{k+1}=\dot x_k+\ddot x_k\Delta t
\]

\[
x_{k+1}=x_k+\dot x_{k+1}\Delta t
\]

代码对应：

```python
self.admittance_velocity += acceleration * dt_s
self.admittance_offset += self.admittance_velocity * dt_s
```

半隐式 Euler 先更新速度，再用新速度更新位置。对质量-弹簧系统而言，它通常比完全显式 Euler 更稳健，但参数过激或时间步过大时仍可能不稳定。

本 Demo 使用：

```python
DEFAULT_TIMESTEP_S = 0.001
```

也就是 `1 ms` 仿真时间步。

## 10. 为什么需要运动边界

如果持续外力很大、刚度很小，理论稳态位移可能超出机械臂工作空间。为防止教学示例生成不合理目标，代码设置了：

| 限制 | 默认值 |
|:---:|:---:|
| 合力模长 | 20 N |
| 合力矩模长 | 5 N·m |
| 平移偏移模长 | 0.15 m |
| 旋转偏移模长 | 20° |
| 线速度模长 | 0.25 m/s |
| 角速度模长 | 0.5 rad/s |
| 单次 IK 关节步长 | 0.02 rad |

限幅按向量模长进行，而不是逐轴截断，因此不会改变向量方向。

当位移达到边界时，对应虚拟速度会被清零，避免积分器继续向边界外累积能量。日志出现 `[LIMITED]` 时，说明外力、运动状态或执行器目标至少有一项被限制。

## 11. 导纳位姿为什么还需要 IK

导纳模型输出的是末端目标：

```text
目标位置 + 目标方向
```

但 MuJoCo 模型的前 7 个执行器需要的是关节目标：

```text
q1, q2, ..., q7
```

因此需要逆运动学把末端误差转换成关节变化：

\[
\Delta q=J^{\#}e
\]

其中：

| 符号 | 含义 |
|:---:|:---:|
| \(e\) | 6 维末端位置和方向误差 |
| \(J\) | 末端相对于 7 个关节的雅可比矩阵 |
| \(J^{\#}\) | 阻尼伪逆 |
| \(\Delta q\) | 本次 IK 迭代的关节变化 |

---

## 12. 阻尼最小二乘微分 IK

普通伪逆在机械臂接近奇异姿态时可能生成非常大的关节变化。代码使用阻尼最小二乘形式：

\[
J^{\#}=J^T(JJ^T+\lambda^2I)^{-1}
\]

因此：

\[
\Delta q=J^T(JJ^T+\lambda^2I)^{-1}e
\]

默认阻尼为：

```python
self.ik_damping = 0.02
```

| IK 阻尼 | 效果 |
|:---:|:---:|
| 太小 | 精度高，但奇异附近可能出现大关节变化 |
| 适中 | 稳定性和跟踪精度较均衡 |
| 太大 | 很稳定，但目标跟踪变慢、残差变大 |

每个仿真时间步只执行两次小 IK 迭代，并把每次关节变化限制为 `0.02 rad`。目标本身由导纳模型平滑生成，所以不需要每一步都运行一个大型非线性优化器。

## 13. 世界坐标系为什么必须写清楚

本 Demo 的：

- wrench；
- 平移偏移；
- 旋转向量；
- 末端位置误差；
- 雅可比矩阵；

都按照世界坐标系解释。Pinocchio 使用：

```python
pin.ReferenceFrame.LOCAL_WORLD_ALIGNED
```

它让末端速度分量的轴方向与世界坐标系对齐，便于和世界坐标系目标误差组合。

如果将来接入真实传感器，而传感器输出的是工具坐标系 wrench，就必须先做坐标变换，不能直接当成世界坐标系输入。

## 14. 为什么不再直接写 `data.qpos`

原代码使用：

```python
self.data.qpos[:7] = self.dof[:7]
```

这会直接改变 MuJoCo 状态，相当于每一步把关节“搬到”IK 结果。它绕过了：

- 位置执行器动态；
- 关节速度连续变化；
- 电机力限制；
- 一部分物理响应。

优化后写入：

```python
self.data.ctrl[:ARM_DOF] = applied_ctrl_rad
```

`panda_pos.xml` 中的执行器再根据位置误差产生作用力，让 MuJoCo 自己积分出下一步关节状态。这样仿真链条更接近真实位置伺服系统。

## 15. 位置执行器与重力前馈

MuJoCo 的位置执行器可近似理解为：

\[
\tau=K_{p,a}(q_{ctrl}-q)-K_{v,a}\dot q
\]

如果直接令：

\[
q_{ctrl}=q_{target}
\]

机械臂需要依靠位置误差产生抵抗重力的力矩，所以实际关节会偏离目标。

代码使用 Pinocchio 计算目标姿态下的重力力矩：

\[
\tau_g=g(q_{target})
\]

再把它换算成位置执行器偏置：

\[
\Delta q_g=\frac{\tau_g}{K_{p,a}}
\]

最终命令为：

\[
q_{ctrl}=q_{target}+\Delta q_g
\]

这不是把重力力矩直接写入执行器，而是利用位置执行器的比例增益生成近似重力前馈。

在默认无界面验证中，这一步将末端稳态跟踪误差从约数厘米降低到了约 `2.66 mm`。

## 16. 每个控制周期的完整顺序

`runFunc()` 每一步执行：

1. 判断合成 wrench 是否已经到启动时间；
2. 限制合力和合力矩；
3. 计算虚拟加速度；
4. 积分虚拟速度和位移；
5. 限制速度、平移偏移和旋转偏移；
6. 从平衡位姿和偏移构造目标末端位姿；
7. 用阻尼最小二乘 IK 更新关节目标；
8. 限制关节目标在 Pinocchio 关节范围内；
9. 计算重力前馈位置偏置；
10. 按执行器 `ctrlrange` 限制最终关节命令；
11. 写入 `data.ctrl[:7]`；
12. 记录 wrench、偏移、目标位置和实际位置；
13. 按固定间隔打印一行状态。

## 17. 日志是什么意思

示例：

```text
t= 2.000 s | F=[ 0.  0. -5.] N | offset=[0. 0. -85.] mm | tracking error=2.8 mm | IK error=1.2e-05
```

| 字段 | 含义 |
|:---:|:---:|
| `t` | MuJoCo 仿真时间 |
| `F` | 当前世界坐标系合成力，单位 N |
| `offset` | 导纳模型产生的 XYZ 平移偏移，单位 mm |
| `tracking error` | 实际末端位置与目标位置之差 |
| `IK error` | 最后一次微分 IK 迭代前的 6 维位姿误差范数 |
| `[LIMITED]` | 至少一项安全边界被触发 |

`tracking error` 和 `IK error` 不是同一件事：

- IK error 描述运动学关节目标能否逼近末端目标；
- tracking error 还包含 MuJoCo 位置执行器和动力学产生的实际跟踪偏差。

## 20. 如何调导纳参数

推荐一次只调一个方向。例如只研究 Z 轴时，重点修改各数组的索引 2。

### 想让同样的力产生更大稳态位移

降低刚度：

```python
virtual_stiffness=(50, 50, 25, 10, 10, 10)
```

此时理论 Z 稳态位移变为：

\[
-5/25=-0.2\ \text{m}
\]

但程序的平移边界是 `0.15 m`，因此最终会被限制并出现 `[LIMITED]`。

### 想让初始响应更快

降低虚拟质量：

```python
virtual_inertia=(10, 10, 5, 1, 1, 1)
```

### 想减少振荡

提高阻尼：

```python
virtual_damping=(20, 20, 30, 4, 4, 4)
```

### 一个常用参考：临界阻尼

单轴二阶系统的临界阻尼是：

\[
B_{critical}=2\sqrt{MK}
\]

它可以作为初始估算，但机器人 IK、位置执行器、离散时间和限幅都会影响实际表现，所以仍需要在仿真中观察调整。

## 21. 推荐学习实验顺序

### 实验一：默认 Z 向恒力

保持 `Fz=-5 N`，确认偏移最终接近 `-100 mm`。

### 实验二：改变力的大小

依次测试：

```text
Fz = -2.5、-5、-7.5 N
```

观察稳态位移是否近似满足 `x=F/K`。

### 实验三：只改变虚拟质量

比较 Z 轴虚拟质量 `5、10、20 kg`。稳态位置应基本相同，但到达稳态的速度不同。

### 实验四：只改变虚拟阻尼

比较 Z 轴阻尼 `5、20、45 N·s/m`，观察过冲、振荡和响应速度。

### 实验五：只改变虚拟刚度

比较 Z 轴刚度 `25、50、100 N/m`，验证持续力下位移与刚度近似成反比。

### 实验六：改成旋转力矩

把 wrench 改为绕 Z 的小力矩，观察旋转向量曲线和机械臂腕部运动。

### 实验七：故意触发边界

降低刚度或增大外力，观察 `[LIMITED]`，并确认位移不会超过代码规定的范围。

## 22. 它和阻抗控制有什么区别

导纳与阻抗经常混淆。

| 对比项 | 导纳控制 | 阻抗控制 |
|:---:|:---:|:---:|
| 典型输入 | 力/力矩 | 位置/速度误差 |
| 典型输出 | 目标运动 | 力/力矩 |
| 直观问题 | 受到这个力后该怎么动 | 偏离目标后该施加多大力 |
| 本仓库示例 | `panda_dynamics_admittance.py` | `panda_dynamics_hold.py` |

本 Demo 是：

```text
wrench → 位姿偏移
```

hold Demo 是：

```text
关节位置误差 → 关节力矩
```

---

## 23. 它和 drag、hold Demo 的区别

| Demo | 核心输入 | 是否有固定返回目标 | 主要输出 |
|:---:|:---:|:---:|:---:|
| `panda_dynamics_drag.py` | 鼠标外力和关节速度 | 默认没有 | 关节力矩 |
| `panda_dynamics_hold.py` | 关节位置/速度误差 | 有，启动关节姿态 | 关节力矩 |
| `panda_dynamics_admittance.py` | 合成末端 wrench | 有，初始末端平衡位姿 | 末端偏移，再转为关节位置目标 |

导纳 Demo 的重点不是“直接抵抗外力”，而是规定受到外力后允许产生怎样的柔顺运动。

## 24. 鼠标拖动是不是导纳输入

不是。

MuJoCo viewer 的鼠标扰动属于仿真外力，但当前 Demo 的导纳方程没有读取鼠标扰动力，也没有读取 `xfrc_applied` 或六维力传感器。

当前导纳输入来自：

```python
self.external_wrench_world
```

鼠标仍可能扰动机器人本体，但位置执行器会尝试继续跟踪导纳生成的目标。要让鼠标外力真正驱动导纳模型，需要可靠地读取该外力、明确参考坐标系，并处理偏置和滤波。

---

## 25. 如何接入真实或仿真的力传感器

实际工程中应把 `_active_wrench_world()` 的合成输入替换为测量链路：

```text
传感器原始 wrench
    ↓
零点偏置补偿
    ↓
重力和工具负载补偿
    ↓
低通滤波
    ↓
工具/传感器坐标系转换到世界坐标系
    ↓
死区和幅值限制
    ↓
导纳模型
```

需要特别确认：

| 项目 | 常见风险 |
|:---:|:---:|
| 力与力矩顺序 | 传感器可能使用不同排列 |
| 坐标系 | 传感器系、工具系、基座系不能混用 |
| 力矩参考点 | 改变参考点会产生力矩平移项 |
| 符号方向 | “环境作用于机器人”和“机器人作用于环境”符号相反 |
| 偏置 | 很小的恒定偏置也会造成持续位移 |
| 噪声 | 导纳积分会把低频偏差累积成运动 |

本示例不控制真实硬件，不能直接作为实机安全控制器使用。

## 26. 原代码的问题与优化结果

| 原实现 | 问题 | 优化后的处理 |
|:---:|:---:|:---:|
| 通用类名 `PandaEnv` | 看不出示例目的 | 改为 `PandaAdmittanceDemo` |
| 大量未使用导入 | 增加依赖和阅读负担 | 只保留实际使用模块 |
| `desired_pos` 与 `start_ee_pos` 共用数组 | 固定参考位姿会被一起修改 | 平衡位姿和动态偏移独立保存 |
| 使用实际跟踪误差作为虚拟弹簧状态 | 导纳内部状态含义混乱 | 弹簧直接作用于导纳偏移 |
| 硬编码索引 3 的 `-5` | 实际是旋转力矩，不是平移力 | 默认明确为 Z 向 `-5 N` |
| 绘制 X 速度但输入旋转轴 | 图和实验不对应 | 分别绘制目标、实际、偏移和 wrench |
| 欧拉角直接差分和积分 | 有跳变和万向锁风险 | 使用旋转矩阵与旋转向量 |

| 没有外力和运动边界 | 可能生成不可达或危险目标 | 增加 wrench、速度、位移和 IK 限制 |
| 没有模型维度和 frame 检查 | 模型不匹配时错误隐蔽 | 初始化时明确校验 |
| 实时 PyQt 绘图耦合控制循环 | 影响性能且不利于无界面验证 | 有界记录，关闭 viewer 后绘图 |

## 27. 常见问题

### 27.1 为什么持续施加力后不会一直运动

因为存在虚拟弹簧。位移增大后，弹簧恢复力也增大，最终与外力平衡。

如果刚度设为零，持续力就没有静态平衡点，系统会受到速度限制或位移限制。

### 27.2 为什么刚开始不是瞬间移动 100 mm

虚拟质量限制加速度，虚拟阻尼抑制速度，所以目标位移是逐渐形成的。

### 27.3 为什么实际位置和目标位置不完全重合

原因可能包括：

- 位置执行器有限增益；
- Pinocchio 与 MuJoCo 模型差异；
- IK 阻尼和每步步长限制；
- 目标仍在运动；
- 关节或执行器限制；
- 目标接近奇异或不可达区域。

### 27.4 为什么设置很大的力后位移没有继续增加

力会先被限制到 `20 N`，平移偏移还会被限制在 `0.15 m`。这是预期安全行为。

### 27.5 为什么不使用真实 Panda 质量作为虚拟质量

导纳参数描述期望交互行为，不是机械臂真实动力学参数。真实机器人动力学由底层系统承担，导纳模型是在其上生成柔顺运动目标。

### 27.6 为什么还要重力前馈，位置执行器不是会保持位置吗

有限比例增益必须依靠位置误差产生重力力矩。重力前馈提前提供等效控制偏置，可以显著减小稳态位置误差。

### 27.7 能不能直接把输出改成关节力矩

可以，但那会变成“导纳外环 + 力矩内环”，需要额外设计关节或任务空间跟踪控制器，并处理力矩限制与稳定性。当前示例选择位置执行器是为了让教学链路更直观。

## 28. 当前实现的边界

这个 Demo 仍然是教学示例，不是完整工业导纳控制器：

- 使用对角、解耦的 6 维虚拟参数；
- 使用合成恒定 wrench；
- 没有真实力传感器偏置与滤波；
- 没有碰撞感知 IK；
- 没有零空间姿态优化；
- 没有机械臂自碰撞约束；
- 使用局部微分 IK，极端目标不保证可达；
- 重力前馈通过位置偏置近似实现；
- 没有真实硬件急停和安全监控。

这些限制不妨碍它用于理解“力如何通过导纳模型变成运动目标”。

## 29. 最值得记住的代码主线

先忽略日志和绘图，只看以下逻辑：

```python
acceleration = (
    wrench_world
    - virtual_damping * admittance_velocity
    - virtual_stiffness * admittance_offset
) / virtual_inertia

admittance_velocity += acceleration * dt_s
admittance_offset += admittance_velocity * dt_s
target_position = equilibrium_position + admittance_offset[:3]
```

它表达的是：

```text
外力推动虚拟质量
阻尼反对运动
弹簧反对偏离平衡点
积分得到位移
位移叠加到初始末端位姿
```

后面的 IK 和位置执行器只是负责让真实仿真机械臂跟上这个目标。

## 30. 总结

这个 Demo 的核心方程是：

\[
\boxed{M_d\ddot x+B_d\dot x+K_dx=F_{ext}}
\]

它将世界坐标系 wrench 转换成一个受控、平滑且有限的末端位姿偏移。随后：

1. 旋转向量和位置偏移构造目标末端位姿；
2. 阻尼最小二乘 IK 把末端误差转换为关节目标；
3. 重力前馈减小位置执行器的静态误差；
4. MuJoCo 根据位置执行器命令推进真实动力学状态。

最重要的理解是：

> 导纳控制不是直接“输出一个力去顶住环境”，而是规定“测到这样的力后，机械臂应该允许自己产生怎样的运动”。
